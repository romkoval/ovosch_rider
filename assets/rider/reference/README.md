# Эталонный пакет для подготовки `rider.glb`: велосипед, скелет, атласы

Для того, кто готовит модель гонщика `rider.glb`: доводка модели в Blender (в том числе
сгенерированной по фото) или моделирование с нуля. Контракт модели — ТЗ
`docs/game/rider-artist-brief.md` и раздел «Гонщик» `docs/game/art-bible.md`. Все файлы
собраны автоматически из кода игры, поэтому числа в них совпадают с таблицами ТЗ. Сами файлы
не меняйте и в `rider.glb` не экспортируйте.

## Как открыть в Blender

File → Import → glTF 2.0, настройки по умолчанию (в том числе «+Y Up»). Файлы уже в осях ТЗ
(раздел 4): Z вверх, гонщик смотрит в −Y (вид спереди — Numpad 1), левая сторона +X,
начало координат (0, 0, 0) — на земле под осью шатунов, 1 единица = 1 метр. Поворот и масштаб
у всех объектов — 0° и 1. Если после импорта велосипед лежит на боку или смотрит в +Y, значит
при импорте была выключена опция «+Y Up»: импортируйте заново с ней.

## Что в каталоге

| Файл | Что это | Зачем |
|---|---|---|
| `bike_reference.glb` | велосипед игры в рабочей геометрии: `bike_frame` (рама, вилка, штырь, руль с тормозными ручками), `saddle` (седло отдельным объектом — поверхность посадки), `wheel_front`, `wheel_rear`, `crankset` (шатуны, звезда, контактные педали). Шатуны в положении rest: правая педаль впереди горизонтально (φ = 90°), левая сзади | посадить гонщика на велосипед (ТЗ раздел 6) |
| | пустые объекты `pt_*` — точки посадки: `pt_saddle_S` — верх седла под точкой опоры таза (0, 0.23, 0.965); `pt_grip_L`, `pt_grip_R` — центр ладони на тормозной ручке (±0.21, −0.62, 0.885); `pt_cleat_R_pedal_axis` — ось правой педали, на ней центр шипа `cleat.R` (−0.115, −0.17, 0.27); `pt_bb` — ось шатунов (0, 0, 0.27); `pt_axle_rear`, `pt_axle_front` — оси колёс | сверить кости-сокеты с велосипедом |
| `rider_rig_reference.glb` | арматура `rider_rig` из 25 костей ТЗ (раздел 5.1) в позе привязки, с теми же именами (`pelvis`, `thigh.L`, `grip.R`, `hair_tail.1`…) и иерархией; оси костей — по разделу 5.3 (Y вдоль кости к окончанию из 5.1, X параллельна X мира); сетка `rig_joints` — метки суставов: оранжевые октаэдры на началах деформирующих костей, голубые (меньше) — на сокетах `grip`, `cleat`, `heel` | сверить свою арматуру `rider_rig` (начала костей — в ±5 мм от этих) или взять её за основу |
| `rider_atlas_preview.png` | атлас 1024 × 256, 32 колонки по 32 px: колонка k — цвет региона k во внешности по умолчанию, по вертикали — тон (0.6 внизу, 1.4 вверху, середина — обычный цвет). У колонки 19 (линза) верхняя четверть — цвет блика | назначить в `M_rider` как Base Color, чтобы видеть цвета в окне Blender (ТЗ раздел 10) |
| `rider_atlas_id.png` | тот же формат: 32 контрастных цвета с номером колонки, тёмная линия по границам колонок; колонки 23–31 (велосипед) помечены крестом — их не используйте | проверить, что острова UV лежат в своих колонках с отступом 10 % от краёв |
| `rider_contract.json` | контракт в машиночитаемом виде (координаты Blender, метры): 25 костей — начало, окончание, оси X/Y/Z, Deform (выкл. у 6 сокетов); контрольные позы обеих ног при φ 0…345° шаг 15° (шип на оси педали, угол стопы по кривой θ(φ), колено) и таблица 5.4; покачивание (5.4); точки и размеры велосипеда; ракурсы §14; регионы и правила атласа | скрипты в Blender (сборка арматуры, проверки), конвейер доводки |

Педали стоят так, как в игре стопа: левая — под углом стопы при своём положении шатуна, правая —
под подошвой правой туфли позы привязки (носок вниз на 8°). У левой стопы в позе привязки
педали нет — так и задумано (ТЗ раздел 5.2). Центр шипа — на оси педали: верх корпуса педали
на 2 мм ниже оси.

После импорта в Blender объект арматуры называется `rider_rig`, кости смотрят вдоль своих
звеньев, крен — по X мира. Длину костей импорт Blender выбирает сам (по расстоянию до дочерней
кости); движок длины и окончания не читает — для сверки важны имена, родители и начала костей.
Импорт Blender 4.2 может добавить служебный объект `Icosphere` (форма отображения костей) —
его можно удалить. У сокетов после импорта стоит флажок Deform: в своей модели весов на них не делайте (ТЗ 5.1).
Метки `rig_joints` привязаны к костям с весом 1 — это только метки, в `rider.glb` их не берите.
Контрольные позы ног для проверки весов — ТЗ раздел 5.4.

## Для конвейера доводки (вариант Г, `scripts/blender/`)

| Файл | Шаг конвейера (арт-библия «Вариант Г») |
|---|---|
| `rider_contract.json` | 3 — A-поза контрактного скелета (длины костей); 5 — rest (начала, окончания, оси); 7 — арматура `rider_rig` (`scripts/blender/build_rig.py`) и контрольные позы для отчёта по весам; 8 — регионы, отступ 10 %, колонки велосипеда 23–31 не используются; 11 — проверки Т2, Т5, Т6 |
| `bike_reference.glb` | 5 — посадка: верх `saddle` (ни одна вершина таза и шорт не ниже), `pt_grip_*`, `pt_cleat_R_pedal_axis`; 7 — контрольные позы (таз и бёдра в седле); кадры ракурсов |
| `rider_rig_reference.glb` | сверка арматуры, собранной из JSON (тест `scripts/blender/tests/test_rig.py`, ±1 мм, оси ±0.05°) |
| `rider_atlas_preview.png` | 8 — превью регионов в Blender и в кадрах (`render_views.py`); в `rider.glb` не экспортируется |
| `rider_atlas_id.png` | 8 — ручная проверка островов UV по колонкам |

- Тон в атласе — множитель цвета региона **в линейном пространстве**: цвет = sRGB→linear(цвет
  региона) × (0.6 + 0.8 · V), обратно в sRGB (`RiderRegions.preview_color`; в JSON —
  `tone_space: linear`). Атлас-превью нарисован так же.
- Чего в пакете нет и где взять: таблицы обхватов `m`/`f`, границы регионов по размерам,
  бюджеты сеток, A-поза — `scripts/blender/pipeline_data.json` (со ссылками на спеку);
  покачивание и контрольные позы — в `rider_contract.json`, словами — бриф §5.4; проверки
  Т1–Т8 и чек-лист Г1–Г16 — бриф §14; кадры `reference/`, `before/`, `world/` — game-designer.

## Для проекта

- Собирается сценарием `./scripts/rider_artist_kit.sh` (Godot 4.7, headless;
  содержимое файлов строит `scripts/dev/rider_reference_pack.gd`) из
  `src/scene3d/rider_rig.gd` (скелет, оси костей, точки посадки, ракурсы, контрольные позы),
  `src/scene3d/rider_model.gd` (велосипед, `reference_kits`), `src/scene3d/rider_regions.gd`
  (регионы, атласы) и `src/profiles/rider_look.gd` (цвета пресета `classic`). Сборка
  воспроизводима побайтно, в том числе между патч-версиями Godot 4.7 (в `asset.generator`
  glTF нет номера сборки). После правки любого из этих файлов пакет пересобирается; тест
  `tests/integration/test_rider_artist_kit.gd` падает, если файлы устарели.
- Проверка в Blender (оси, масштаб, кости, седло, ручки — импорт с настройками по умолчанию):
  `/opt/bpy/bin/python scripts/dev/check_rider_pack_blender.py` или
  `blender -b -P scripts/dev/check_rider_pack_blender.py`.
- `.gdignore`: каталог не импортируется редактором и не попадает в сборку приложения.
- Кадры ракурсов (ТЗ раздел 14, плюс `rear_low` ред. 3): `./scripts/rider_views.sh <каталог>`;
  велосипед без гонщика — `BIKE_ONLY=1 ./scripts/rider_views.sh <каталог> side_r,hips_r`.
- Кадры `reference/`, `before/`, `world/` (ТЗ раздел 18) к пакету добавляет game-designer.
