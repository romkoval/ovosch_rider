# Пакет для 3D-художника: велосипед, скелет, атласы

К ТЗ «Велосипедист для ovosch-rider» (`rider-artist-brief.md`). Все файлы сделаны
автоматически из кода игры, поэтому числа в них совпадают с таблицами ТЗ. Ничего в них не
меняйте и в `rider.glb` не экспортируйте.

## Как открыть в Blender

File → Import → glTF 2.0, настройки по умолчанию (в том числе «+Y Up»). Файлы уже в осях ТЗ
(раздел 4): Z вверх, гонщик смотрит в −Y (вид спереди — Numpad 1), левая сторона +X,
начало координат (0, 0, 0) — на земле под осью шатунов, 1 единица = 1 метр. Поворот и масштаб
у всех объектов — 0° и 1. Если после импорта велосипед лежит на боку или смотрит в +Y, значит
при импорте была выключена опция «+Y Up» — импортируйте заново с ней.

## Что в каталоге

| Файл | Что это | Зачем |
|---|---|---|
| `bike_reference.glb` | наш велосипед в рабочей геометрии: `bike_frame` (рама, вилка, седло, руль с тормозными ручками), `wheel_front`, `wheel_rear`, `crankset` (шатуны, звезда, контактные педали). Шатуны в положении rest: правая педаль впереди горизонтально (φ = 90°), левая сзади | посадить гонщика (раздел 6) |
| | пустые объекты `pt_*` — точки посадки: `pt_saddle_S` — верх седла под точкой опоры таза (0, 0.23, 0.965); `pt_grip_L`, `pt_grip_R` — центр ладони на тормозной ручке (±0.21, −0.62, 0.885); `pt_cleat_R_pedal_axis` — ось правой педали, на ней центр шипа `cleat.R` (−0.115, −0.17, 0.27); `pt_bb` — ось шатунов (0, 0, 0.27); `pt_axle_rear`, `pt_axle_front` — оси колёс | сверить кости-сокеты с велосипедом |
| `rider_rig_reference.glb` | арматура из 25 костей ТЗ (раздел 5.1) в позе привязки, с теми же именами (`pelvis`, `thigh.L`, `grip.R`, `hair_tail.1`…) и иерархией; сетка `rig_joints` — метки суставов: оранжевые октаэдры на началах деформирующих костей, голубые (меньше) — на сокетах `grip`, `cleat`, `heel` | сверить свою арматуру `rider_rig`: начала костей — в ±5 мм от этих |
| `rider_atlas_preview.png` | атлас 1024 × 256, 32 колонки по 32 px: колонка k — цвет региона k во внешности по умолчанию, по вертикали — тон (0.6 внизу, 1.4 вверху, середина — обычный цвет). У колонки 19 (линза) верхняя четверть — цвет блика | назначить в `M_rider` как Base Color, чтобы видеть цвета в окне Blender (раздел 10) |
| `rider_atlas_id.png` | тот же формат: 32 контрастных цвета с номером колонки, тёмная линия по границам колонок; колонки 23–31 (велосипед) помечены крестом — их не используйте | проверить, что острова UV лежат в своих колонках с отступом 10 % от краёв |

Педали стоят так, как в игре стопа: левая — под углом стопы при её положении, правая — под
подошвой правой туфли позы привязки (носок вниз на 8°). Левая стопа rest педали не имеет — так и
задумано (раздел 5.2). Ось шатуна — центр шипа: верх корпуса педали на 2 мм ниже оси.

Арматура после импорта в Blender может называться `Armature` — для сверки важны имена костей и
положения их начал, не имя объекта. Кончики костей (tail) импорт Blender ставит сам, движок их
не читает.

## Для проекта (художнику не нужно)

- Собирается сценарием: `./scripts/rider_artist_kit.sh` (Godot 4.7 headless) из
  `src/scene3d/rider_rig.gd` (скелет, точки посадки, ракурсы), `src/scene3d/rider_model.gd`
  (велосипед, `reference_kits`), `src/scene3d/rider_regions.gd` (регионы, палитра `classic`,
  атласы). После правки любого из них пакет пересобирается; тест
  `tests/integration/test_rider_artist_kit.gd` падает, если файлы устарели.
- `.gdignore`: каталог не импортируется редактором и не попадает в сборку приложения.
- Кадры ракурсов брифа раздел 14: `./scripts/rider_views.sh <каталог>` (без гонщика —
  `BIKE_ONLY=1`).
- Кадры `reference/`, `before/`, `world/` (бриф раздел 18) к пакету добавляет game-designer.
