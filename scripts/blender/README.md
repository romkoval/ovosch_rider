# Конвейер доводки ИИ-модели гонщика в Blender (T-143)

Для technical-artist. Арт-библия «Гонщик» → «Вариант Г»: сырой GLB сервиса генерации по фото
владельца → `rider.glb` по контракту (бриф `docs/game/rider-artist-brief.md` §3–§6, §10–§12,
§14). Шаги скриптами, повторяемо: сырой файл можно заменить и прогнать заново.

## Запуск

```bash
./scripts/rider_refine.sh <сырой.glb> [--landmarks J] [--from N] [--to M] [--work DIR] [--retopo project|decimate]
./scripts/rider_refine.sh --compare a.glb b.glb c.glb     # шаг 1 по 2–3 вариантам сырья, выбор лучшего
scripts/blender/test.sh [-k шаблон] [--update-fixture]   # тесты конвейера (≈ 40 с)
```

Blender ищет `scripts/blender/env.sh`: переменная `BLENDER_PY` — Python с модулем `bpy`
(облако: `/opt/bpy/bin/python`, ставит `scripts/cloud/setup.sh`) или бинарник Blender 4.2+
(Mac: `BLENDER_PY=/Applications/Blender.app/Contents/MacOS/Blender`). Все скрипты работают в
обоих режимах (`python script.py …` и `blender -b -P script.py -- …`).

Код выхода: 0 — шаги пройдены; 1 — ошибка шага (строка `ШАГ N (шаг): объект: что не так`,
конвейер стоит) или падение скрипта (трейсбек); 2 — неверные аргументы. Скрипты выходят через
`common.run_main` → `os._exit(код)`: bpy-модуль падает SIGSEGV (139) при штатном выходе после
экспорта glTF, а файлы к этому моменту уже записаны.

## Где что лежит

- Рабочий каталог — **вне git**: по умолчанию `reference/ai/work/<имя сырого>/` (`reference/`
  в `.gitignore`). В нём `NN_<шаг>.blend` после каждого шага, `report.txt` (строка на шаг:
  что сделано, метрики, предупреждения), `report.json`, `state.json`, итог `rider.glb` и
  `rider.blend`. В `assets/rider/` итог кладёт T-106c′ (после записи REQ-D3D-09 п.9 (а) и Н-45).
- Сырьё и фото владельца — `reference/ai/` (вне репозитория, в отчёты и `docs/` не попадают).
- Продолжить с шага N: `--from N` — берётся `(N−1)_*.blend` из того же `--work`. Повторить
  один шаг: `--from N --to N`.

## Ориентиры `landmarks.json`

Рядом с сырым файлом: `<имя>.landmarks.json` (или `landmarks.json`, или `--landmarks`).
Координаты — как их показывает Blender после импорта сырого файла с настройками по умолчанию
(в единицах файла, оси файла — конвейер сам повернёт и переведёт в метры):

```json
{"joints": {"pelvis": [x, y, z], "spine": [...], "chest": [...], "neck": [...], "head": [...], "crown": [...],
            "upperarm.L": [...], "forearm.L": [...], "hand.L": [...], "grip.L": [...],
            "thigh.L": [...], "shin.L": [...], "foot.L": [...], "cleat.L": [...], "heel.L": [...], "… .R": [...]}}
```

Имена — кости контракта (бриф 5.1): `pelvis` — середина между седалищными буграми, `spine` —
поясница (≈ 0.22 м над `pelvis`), `chest` — низ грудной клетки сзади, `neck` — основание шеи,
`head` — основание черепа (атланто-затылочный сустав), `crown` — макушка (верхняя точка головы); плечевой сустав, локоть, запястье, центр ладони;
тазобедренный сустав, колено, голеностоп, центр шипа (подушечка стопы), пятка на линии подошвы.
Как ставить: в Blender пустые объекты (Add → Empty) с этими именами на суставы скана, затем
`{"joints": {o.name: list(o.location) for o in bpy.context.selected_objects}}` в JSON.
Синтетика пишет ориентиры сама. «.L» — левая сторона самого человека (+X брифа §4), не левая
со стороны зрителя: перепутанные стороны разворачивают фигуру, шаг 1 останавливается.

## Данные и контракт

- `assets/rider/reference/rider_contract.json` — контракт из кода (`RiderRig`, `RiderRegions`):
  кости (начало, окончание, оси, Deform), контрольные позы ног φ 0…345° шаг 15° и строка rest
  таблицы контрольных поз, A-поза (раздел `apose` — из `pipeline_data.json`, один источник),
  покачивание, точки велосипеда, ракурсы, регионы. Собирает `./scripts/rider_artist_kit.sh` вместе с пакетом;
  GUT `test_rider_artist_kit` падает, если файл устарел.
- `scripts/blender/pipeline_data.json` — числа спеки, которых нет в коде: A-поза (рост 1.75,
  ось `head` 20°, макушка 0.15 вверх и 0.03 вперёд; ред. 4.2), голова (размер, центр в rest),
  таблицы фигур `m`/`f`, станции обхватов, границы регионов, бюджеты, сегментация, веса,
  допуски седла, пороги проверки сырья; у каждого числа ссылка на подраздел спеки.
  `tests/test_data.py` сверяет их с арт-библией, брифом и контрактом.
- `build_rig.py <out.blend> [--apose] [--glb out.glb]` — арматура `rider_rig` из контракта
  (rest или A-поза).
- `make_synthetic.py [каталог] [вариант …]` — синтетический «сырой» вход: `m`, `cm`, `axes`,
  `bad_notex`, `bad_legs`, `bad_two` (по умолчанию в `reference/ai/synthetic/`).
- `render_views.py <файл.blend> <каталог> [work,side_r,…]` — кадры ракурсов (Cycles, CPU,
  32 сэмпла + OpenImageDenoise) с велосипедом и цветами атласа-превью.
- `tests/fixtures/rider_synthetic/rider_synthetic.glb` — выход конвейера на синтетике, источник
  модели GUT `test_rider_rig_contract` (сквозная проверка в Godot); пересборка —
  `scripts/blender/test.sh --update-fixture`.
