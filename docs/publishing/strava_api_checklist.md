# Чеклист Strava API: регистрация, ревью, брендбук (REQ-STR-01 крит. 6, 7, 9; ТЗ раздел 3; этап 8)

Реализация OAuth и очереди выгрузки — в `src/integrations/strava/` (T-046..T-048); здесь — то, что
делается в кабинете Strava и в дизайне и не проверяется в контейнере. Пункты `[ ]` — чеклист владельца.

## 1. Регистрация API-приложения

- [ ] Войти на `https://www.strava.com/settings/api` под аккаунтом владельца (приложение привязывается
      к одному аккаунту Strava — лучше к аккаунту разработчика/организации, а не к личному спортивному).
- [ ] Заполнить: Application Name — `ovosch-rider` (без слова «Strava» в названии — запрещено брендбуком),
      Category — **Training**, Club — пусто, Website — URL страницы приложения/политики,
      Application Description, **Authorization Callback Domain**:
      - для loopback-redirect на десктопе (В-6) — `localhost` (Strava принимает `localhost`/`127.0.0.1`
        для dev; `redirect_uri` в запросе — `http://127.0.0.1:<port>/callback`, порт любой);
      - для мобильной схемы `ovoschrider://strava` домен не нужен: Strava проверяет только домен для
        `http(s)`-redirect; при проблемах — переключить мобильные на universal link `https://<ДОМЕН>/strava/callback`
        и вписать `<ДОМЕН>`. Решение зафиксировать в `docs/backlog.md` (вопрос к В-6).
- [ ] Загрузить иконку приложения (показывается на экране согласия Strava).
- [ ] Получить `Client ID` и `Client Secret`. **Секрет в репозиторий не попадает** (REQ-STR-01 крит. 5):
      dev-сборки — `user://secrets.cfg` по образцу `secrets.example.cfg` или переменные
      `OVOSCH_STRAVA_CLIENT_ID`/`OVOSCH_STRAVA_CLIENT_SECRET`; магазинные сборки — подстановка на машине сборки
      (CI-секрет → генерация `user://secrets.cfg`-аналога внутри пакета или compile-time define в GDExtension).
      Альтернатива без секрета в клиенте — серверный обмен кода (В-6, решает владелец).
- [ ] Scope, который запрашивает приложение: `activity:write,read` (создание активностей + базовые данные
      атлета). `activity:read` не нужен, пока нет чтения чужих заездов; `profile:read_all` не нужен.

## 2. Лимит одного атлета и ревью Strava

- Новое API-приложение имеет **Athlete Capacity = 1**: авторизоваться может только владелец приложения.
  Для публичного релиза лимит снимается только после **Strava API Program review**.
- [ ] Подать заявку на ревью **до** публичного релиза (ТЗ раздел 3). Форма — «Strava Developer Program /
      API Application Review» (ссылка в кабинете API Settings → «Request Capacity Increase», либо
      `https://developers.strava.com/` → Getting Started → Submit for Review). Срок рассмотрения — недели; закладывать в план этапа 8.
- [ ] В заявке требуются: описание приложения и как оно использует данные; скриншоты экрана подключения
      с кнопкой «Connect with Strava» и экранов, где показаны данные Strava (с «Powered by Strava»);
      ссылка на политику конфиденциальности; подтверждение соблюдения API Agreement; видео или TestFlight-доступ.
- [ ] Условия Strava API Agreement, которые надо соблюдать и заявить:
      - данные Strava не используются для обучения моделей/ИИ, не передаются третьим лицам, не агрегируются с другими пользователями;
      - при отзыве доступа (deauthorize) приложение удаляет токены и связанные данные Strava (у нас токены — `SecureStore`, кэш данных Strava не ведём);
      - нельзя показывать данные одного атлета другому без разрешения (не применимо — приложение однопользовательское на устройстве);
      - при авторизации показывать именно экран согласия Strava, не подменять UI, не хранить пароль.
- [ ] До прохождения ревью TestFlight-тестировщики не смогут подключить Strava — сообщать им об этом;
      экран привязки должен корректно показывать ошибку Strava о лимите (HTTP 403/400 на `/oauth/token`).

## 3. Брендбук (Strava Brand Guidelines)

Источник: `https://developers.strava.com/guidelines/` (Brand Guidelines, Logo & Button assets).
Ассеты (PNG/SVG кнопок и логотипов) скачиваются оттуда и кладутся в `assets/branding/strava/` без изменений.

- [ ] **Кнопка «Connect with Strava»** — единственный допустимый способ инициировать OAuth:
      - использовать официальный ассет (оранжевый фон, белая надпись, две плотности `@1x`/`@2x`; есть вариант «Connect with Strava» и «Connect» в оранжевом);
      - не менять цвет, шрифт, пропорции, скругления; масштабировать только пропорционально; минимальная высота — как у официального
        `@1x` ассета (48 px при 1x по актуальному набору — сверить с загруженным файлом);
      - не меньше и не менее заметна, чем кнопки подключения других сервисов (у нас — Intervals.icu): одинаковая высота в списке интеграций;
      - свободное поле вокруг кнопки — не менее высоты буквы «S» из надписи.
- [ ] **Логотип «Powered by Strava»** — обязателен на каждом экране, где отображаются данные, полученные из Strava
      (у нас: статус выгрузки, ссылка на загруженную активность, имя атлета после привязки):
      - варианты: оранжевый на светлом, белый на тёмном/оранжевом; выбирать по контрасту фона HUD/тёмной темы;
      - ширина не менее минимальной из ассета (ориентир — 100 px при 1x), не растягивать;
      - ставить рядом с данными Strava (нижний угол карточки), а не в футере приложения «вообще».
- [ ] Цвет Strava Orange — брать из ассета, не задавать вручную; в актуальном брендбуке `#FC5200`
      (в более старых материалах встречается `#FC4C02`). Не использовать этот оранжевый как акцент собственного UI.
- [ ] Текст: писать «Strava» с заглавной, не «STRAVA»/«strava»; не употреблять «Strava» в названии и иконке приложения;
      допустимо «Upload to Strava», «Connected to Strava». В магазинах не писать «official»/«partner».
- [ ] Иконка приложения, скриншоты, маркетинг — без логотипа Strava как части собственного бренда.
- [ ] Отвязка: пункт «Disconnect from Strava» в настройках профиля; дополнительно сообщать, что доступ можно отозвать на strava.com → Settings → My Apps.

## 4. Rate limits

- Лимиты по умолчанию для приложения: **100 запросов за 15 минут и 1000 запросов в сутки** (общий лимит; у части
  приложений Strava выдаёт также отдельный лимит на чтение). После ревью лимиты можно повысить по запросу.
  Фактические значения приходят в заголовках ответа `X-RateLimit-Limit` / `X-RateLimit-Usage`
  (формат `15min,daily`) и `X-ReadRateLimit-*`; при превышении — HTTP 429.
- Реализация (T-047/T-048) обязана: обрабатывать 429 с отложенным повтором очереди выгрузки (экспоненциальная пауза,
  не чаще одного повтора на 15-минутное окно), не опрашивать статус загрузки чаще 1 раза в 1–2 с и не более ~10 раз на файл;
  одна выгрузка = `POST /api/v3/uploads` + несколько `GET /api/v3/uploads/{id}` — укладывается в лимит даже при 20 заездах в день.
- [ ] Перед релизом посмотреть фактические лимиты в API Settings и записать их сюда.
