# ТЗ: ovosch-rider — приложение для велотренировок

Oct 2, 2026 · @Roman · ред. 2 — Oct 3, 2026 (графики HUD, свободная езда, трассы с рельефом, оформление меню)

## 1. Назначение и цели

ovosch-rider — кроссплатформенное приложение для тренировок на умном велостанке: берёт тренировку на сегодня из Intervals.icu, проводит её с управлением нагрузкой в ERG-режиме и 3D-визуалом, сохраняет заезд локально и выгружает в Strava.

Цели MVP:

- Замкнуть полный цикл: план → тренировка → сохранение → выгрузка
- Управлять мощностью станка (Tacx Neo) в ERG-режиме с включением и отключением на лету
- Дать базовый 3D-визуал с архитектурным заделом на развитие
- Подготовить продукт к публикации в App Store и Google Play

## 2. Границы MVP

Входит в MVP:

- Несколько пользовательских профилей на одном устройстве
- Загрузка тренировки на сегодня из Intervals.icu
- Импорт тренировок из файлов ZWO и .erg/.mrc
- Проведение структурированной тренировки по интервалам
- Подключение к Tacx Neo и датчикам по BLE
- ERG-режим с включением и отключением
- HUD: целевая и фактическая мощность, зона мощности, пульс, каденс; график плана с фактом мощности и пульса
- Простой 3D-визуал движения по дороге
- Свободная езда без плана по выбранной трассе, SIM-режим (уклон трассы задаёт сопротивление станка)
- Несколько трасс с рельефом и превью профиля высот
- Локальное хранилище заездов с просмотром и экспортом в FIT
- Выгрузка в Strava

Не входит в MVP:

- Калибровка станка из приложения (spin-down)
- Групповые заезды и социальные функции
- Собственная аналитика и расчёт тренировочной нагрузки
- Маршруты по GPX
- Детализированные трассы, кастомизация аватара, соревнования

Требования, вытекающие из публикации:

- Политика конфиденциальности и раскрытие собираемых данных (пульс относится к данным о здоровье)
- Описания использования Bluetooth для App Store (NSBluetoothAlwaysUsageDescription) и разрешения BLE для Android 12+

## 4. Архитектура

Движок — Godot 4.x; работа с Bluetooth вынесена в единый нативный модуль на C++ через GDExtension, весь остальной код общий для всех платформ.

Почему Godot: открытый, экспортирует на все пять целевых платформ, даёт полноценное 3D с заделом на развитие.

BLE-слой — самая трудоёмкая часть. Godot не поддерживает BLE штатно, поэтому модуль инкапсулирует платформенные API и отдаёт в Godot единый интерфейс (сканирование, подключение, подписка на характеристики, запись целевой мощности):

| Платформа | Нативный BLE-API |
| --- | --- |
| iOS, macOS | CoreBluetooth |
| Android | Android BLE API (через JNI) |
| Linux | BlueZ (D-Bus) |
| Windows | WinRT Bluetooth LE |

Слои приложения:

1. Интеграции — Intervals.icu, Strava, импорт ZWO и .erg, авторизация, кэш
2. Профили — данные пользователя, FTP, зоны, привязанные аккаунты и устройства
3. Домен — модель структурированной тренировки, исполнитель интервалов, состояние сессии
4. Устройства — BLE-абстракция, станок и датчики, симулятор устройств для разработки
5. Хранение — локальная БД заездов (SQLite), генерация FIT
6. Представление — 3D-сцена, HUD, экраны профилей, настроек и истории

Приём данных с датчиков и исполнитель тренировки работают независимо от цикла отрисовки, чтобы падение FPS не влияло на запись и управление станком.

## 7. Этапы разработки

Этапы идут последовательно; каждый заканчивается работающим результатом, который можно проверить на станке.

1. **Каркас.** Проект на Godot, профили, модель тренировки, исполнитель интервалов, симулятор устройств. Результат: тренировка проигрывается без железа.
2. **BLE для iOS и macOS.** GDExtension-модуль на CoreBluetooth, FTMS и датчики. Результат: реальное подключение к Tacx Neo.
3. **Тренировка и ERG.** Полный цикл проведения, ERG вкл/выкл, HUD с зонами. Результат: можно тренироваться.
4. **Источники плана.** Intervals.icu и импорт ZWO, .erg/.mrc. Результат: план подтягивается автоматически или из файла.
5. **Хранилище.** Локальная БД, генерация FIT, история, экспорт. Результат: заезды сохраняются и экспортируются.
6. **Strava.** OAuth, очередь выгрузки. Результат: цикл замкнут.
7. **3D-сцена.** Дорога, велосипедист, привязка скорости к мощности. Доработка: графики HUD по референсу, свободная езда с SIM, четыре трассы с рельефом, переработка меню и экранов. Результат: MVP готов.
8. **Публикация iOS и macOS.** Политика конфиденциальности, ревью Strava, OAuth Intervals.icu, TestFlight, App Store.
9. **Android.** Портирование BLE-слоя, Google Play.
10. **Linux и Windows.** Портирование BLE-слоя, выбор каналов распространения.
