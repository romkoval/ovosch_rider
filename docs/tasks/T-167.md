# T-167 — Станок по Tacx FE-C over BLE: определение, подключение, данные `[integration]`

Статус, приоритет и очередь — **только** в таблице `docs/backlog.md` (раздел 2). Здесь — описание, критерии приёмки, история и вердикты.

## Задача

- Исполнитель: developer. Размер: M.
- Зависит от: T-152 (общие файлы `ble_trainer.gd`, `trainer_device.gd`; правило сессии «станок без канала управления»). Уточнения по живому Neo — данные экрана «BLE-отладка» (T-165), не блокируют: критерии — на фикстурах. Н-70 (б), (е) — до ответа по предложениям requirements.
- Почему: решение владельца 2026-10-05 (У-27) — FE-C over BLE в MVP, REQ-DEV-11; эталонный Tacx Neo владельца работает только по FE-C (У-28). Приоритет — ниже WRK-09 (У-29). DEV-11 нарезан на две задачи: данные (эта) и управление (T-168).

## Что сделать

1. Классификация «станок» по сервисам, не по имени (DEV-11 п.1 (а)–(д)): FEC1 в рекламе или после подключения; «каденс» → «станок» после `services_discovered` с FEC1 (запоминается как станок, не датчик профиля); CSC и CPS станка не подписываются и не дублируются в списке; есть и `0x1826`, и FEC1 — подключение по FTMS; фирменный `669AA501-…` не трогается.
2. Подключение (п.2): `subscribe(id, FEC1, FEC2)`, без FTMS Request Control; нет FEC2 — не «подключено», ошибка подключения; нет FEC3 — только данные: ни одного `write`, ERG/сопротивление/SIM недоступны, сессия — `power_meter` по WRK-09 п.1 (б) (правило сессии — из T-152).
3. Кодек FE-C (`src/devices/ble/codecs/`): разбор и сборка ANT-сообщения `A4 09 <ID> <канал> <8 байт> <CS>`; отбрасывание по п.3 без ошибки сессии.
4. Страница 0x19 — мощность (12 бит) и каденс (п.4); страница 0x10 — скорость и пульс станка (п.5); «нет данных» — не 0.
5. Реализация станка FE-C за интерфейсом `TrainerDevice` (п.10, DEV-09 п.1, NFR-06 п.3); в этой задаче команды управления — заглушки «недоступно» (их делает T-168).

## Критерии приёмки

- REQ-DEV-11 п.1 (а)–(д) — `[авто]`: фикстуры `device_found` [FEC1] с тремя именами и без имени → «станок», одинаковый журнал; «Tacx Neo 11565» [0x1816] → «каденс» → после `services_discovered` со списком п.1 (б) → «станок», в датчиках профиля его нет; нет `subscribe` на `0x2A5B`, `0x2A63` у станка; `0x1826` + FEC1 → без `subscribe`/`write` на FEC1; ни одного обращения к `669AA501-…`.
- REQ-DEV-11 п.2 — `[авто]`: подписка на FEC2, без Request Control; без FEC2 — не «подключено», ошибка; без FEC3 — ни одного `write`, сессия `power_meter` (фикстура «FE-C без FEC3» из WRK-09 п.1).
- REQ-DEV-11 п.3 — `[авто]`: сообщение п.4 (а) разбирается; с CS `58`, байтом 1 = `08`, длиной 12, байтом 0 = `A5` — отброшено, сессия и сэмплы идут, ошибки нет.
- REQ-DEV-11 п.4, п.5 — `[авто]`: (а) 250 Вт, 90 об/мин; (б) 1234 Вт, 80 об/мин; (в) «нет данных»; 28.80 км/ч, 36.00 км/ч, `FF FF` — «нет данных»; пульс станка ниже HRS.
- REQ-WRK-09 п.1 (фикстура «FE-C без FEC3» → `power_meter`), п.4 (подписка только на FEC2) — `[авто]`.
- Регрессия: DEV-01, DEV-02, DEV-06, DEV-10 п.1–2 (поиск названий моделей пуст — и в реализации FE-C), DEV-04 п.4, DEV-05 п.2–3, WRK-08 п.4–5; полный прогон зелёный.
