## Карточка

> Заголовок карточки до разделения: T-106a4 — Импорт `rider.glb` и проверки Т1–Т8 `[visual]` — `todo` — P0 (MVP, У-18)

Волна 5, после T-106a3 (TA-1). Исполнитель — technical-artist. Размер M. Зависит: T-106a3.
Почему. Когда придёт блокинг (вариант Г — результат конвейера T-143 по сырью владельца, T-106b′; запасной путь — художник), импорт и все технические проверки должны быть готовым инструментом: проверка версии — часы, а не дни. `rider_check.sh` — общий инструмент T-143 (шаг 11), T-106b′, T-106c′ и запасных T-106b, T-106c.
Что сделать.
1. Сценарий импорта `rider.glb` (headless `--import`): поворот 180° вокруг Y, замена `M_rider` на материал T-106a3, сетки вариантов (`body_m`, `body_f`, `hair_*`, `helmet_*`, `glasses_*`, `shoe_*_L/R`) — в ресурсы, сборка узлов состава на `Skeleton3D` по таблице T-106a1, нормали контура при импорте.
2. Проверки Т1–Т7 брифа (раздел 14) с понятной ошибкой (номер проверки, объект, что не так); Т8 — тестовый набор T-106a2 на импортированной модели для обеих фигур.
3. `scripts/rider_check.sh <rider_vN.glb>` — отчёт Т1–Т8 и кадры ракурсов (T-106a1) для одной версии: инструмент T-106b, T-106c.
4. Источник модели: есть `assets/rider/rider.glb` — модель художника, нет — манекен (до T-106c игра на манекене).
5. Проверка конвейера без художника: синтетический `rider.glb`, собранный сценарием из манекена (`GLTFDocument`: 12 сеток с именами брифа, `rider_rig` 25 костей, один материал `M_rider`), и намеренно испорченные копии (лишняя или переименованная кость, второй материал, `COLOR_0`, грань на границе колонок, вес на сокете, превышен бюджет, масштаб ≠ 1).
6. Где хранить `rider.blend` (в репозитории, Git LFS или у владельца) — предложение в отчёт; окончательно — по Н-45 (вариант Г; при запасном пути — Н-30).
Закрывает: инструмент приёмки REQ-D3D-09 п.1–8 на модели художника; п.7 (проверка бюджета при импорте), п.9 (механизм: тест «для каждого файла ассетов гонщика есть записи в `docs/game/assets.md` и `docs/publishing/licenses.md` с основанием вида (а), (б) или (в); у записи вида (а) непусты поля (1)–(7)» — по REQ-D3D-09 п.9 ред. 3f1a5a4; пока файлов нет — проходит пусто).
Критерии авто: синтетический `rider.glb` импортируется headless, сцена из ≤ 10 узлов, REQ-D3D-09 п.1–7 проходят на нём для `m` и `f`; каждая испорченная копия → понятная ошибка своей проверки Т1–Т7; без `rider.glb` — манекен, все тесты T-106a2, T-106a3 зелёные; тест п.9 есть. Визуально: `rider_check` по синтетической модели — 6 ракурсов, вердикт game-designer «формат кадров годится для отзыва художнику».
