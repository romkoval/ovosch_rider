# T-152 — Тренировка без умного станка: сессия и устройства `[game]`

Статус, приоритет и очередь — **только** в таблице `docs/backlog.md` (раздел 2). Здесь — описание, критерии приёмки, история и вердикты.

## Задача

- Исполнитель: developer (worktree `wt-152`). Размер: M–L.
- Зависит от: — (REQ-WRK-09 заведён, коммит 11a0226; макет T-151 нужен только T-153). T-161 не нужна: станок без Control Point (DEV-10 п.4) делается здесь (см. «Что сделать», п.6).
- Почему: решение владельца 2026-10-07 (У-29, приоритет максимальный) — тренировка по датчику мощности без управляемого станка (у владельца — Quarq, CPS `0x1818`). Закрывает Н-53, Н-54. Это режим сессии `trainer_mode = power_meter`, а не свойство источника.

## Что сделать

Пункты REQ — по редакции `docs/requirements.md` на 2026-10-07 (requirements переносит туда критерии макета T-151; при перенумерации — сверять по тексту).

1. **Выбор режима** (WRK-09 п.1). При старте сессии по устройствам в состоянии «подключено»: управляемый станок (FTMS с `0x2AD9`) → `smart`; иначе источник мощности без управления — измеритель мощности (CPS) или станок без канала управления → `power_meter` (если оба — измеритель); иначе сессии нет. Режим не меняется до конца сессии: управляемый станок, подключившийся во время `power_meter`, не получает ни одного `write`.
2. **Правило старта** (WRK-09 п.2 — логика, без UI; FRD-01 п.4). Модель старта отдаёт один из исходов: «старт `smart`», «старт `power_meter` сразу» (запомненного станка нет, DEV-06 п.1), «нужно подтверждение» (станок запомнен, не подключён), «старта нет» (ни станка, ни источника мощности). «Подключение» и «переподключение» — не «подключено» (п.2 (д)). Одинаково для плана и свободной езды. Диалог, тексты и навигация — T-153.
3. **Источник мощности без управления** за интерфейсом `TrainerDevice` (DEV-09 п.1, NFR-06 п.3; WRK-09 п.11): ни одной команды управления, телеметрия — от CPS / CSC / HRS (DEV-05 п.5) или от станка без канала управления. Способ выбирает developer (реализация «без управления» поверх датчиков в `src/devices/` или иное) — обоснование в отчёте. `WorkoutSession` знает только режим и возможности, не UUID.
4. **План по таймеру** (WRK-09 п.3, WRK-01 п.6): переходы, пауза, пропуск, множитель — как в `smart`; цель — по WRK-02 п.1, 3 с множителем WRK-07, без ограничения DEV-10 п.6; на FreeRide цель «нет данных». Флаг ERG во всех сэмплах — «выкл»; событий переключения ERG нет.
5. **Ни одной команды** (WRK-09 п.4): ни одного `write`; `subscribe` — только `0x2A63`, `0x2A37`, `0x2A5B`, `0x2A19` (у станка без управления — `0x2AD2`, `0x2ADA`). Клавиша E, ERG и сопротивление в `power_meter` ничего не делают на уровне сессии (видимость кнопок — T-153).
6. **Станок без Control Point** (DEV-10 п.4; перенесено из T-161): FTMS без `0x2AD9` — ни `subscribe`, ни `write` на `0x2AD9` (Request Control тоже), подписка на `0x2AD2` (и `0x2ADA`), состояние «подключено» как источник данных, телеметрия по DEV-02 п.2; возможность «нет управления» видна сессии через `TrainerDevice`. Сессия с таким станком — `power_meter`, источник мощности — станок. FE-C без FEC3 (DEV-11 п.2) — здесь только общее правило сессии («станок без канала управления» на фейке/фикстуре); байтовая часть FE-C — T-167.
7. **Сэмплы и обрыв** (WRK-09 п.6, DEV-08 примечание). Мощность — от источника. Каденс — CSC > CPS > станок. Пульс — HRS. Скорость — только по модели с уклоном (`speed_source = модель`), в том числе у станка без управления с полем скорости (У-30). Общее удаление пути «скорость от станка» — T-169.
   Обрыв (WRK-09 п.6 (б), DEV-05 п.2 (б)–(г); У-32): CPS молчит ≥ 5 с или пришёл `disconnected`.
   - Если подключён станок без канала управления — со следующего сэмпла берётся его мощность. CPS вернулся (первый пакет после `connected`) — снова CPS.
   - Иначе мощность «нет данных», не 0, и аватар останавливается (D3D-02 п.7).
   - План идёт дальше, автопаузы нет.
   Переподключение — каждые 5 с; после `connected` — `discover_services` и повторная подписка на `0x2A63`, ни одного `write`. Тот же приоритет в режиме `smart` — T-170. Если в T-152 он получится общим для всех режимов, сообщить в отчёте: T-170 сведётся к проверке.
8. **Свободная езда** (WRK-09 п.7 — модель и журнал): позиция, дистанция, высота и скорость — по модели с уклоном (вводный абзац FRD; FRD-04 п.2 в части s, п.7–9) от мощности источника; станку ничего не уходит; крутизна SIM ни на что не влияет (решение координатора 2026-10-07: свободная езда по модели с уклоном). HUD свободной езды — T-153.
9. **Сохранение** (WRK-09 п.8, LOC-01 п.1): поле метаданных `trainer_mode` (`smart` / `power_meter`; без поля читается как `smart`); `trainer_source` (T-160) — источник мощности (`ble` / `emulator`); итог, FIT, очередь Strava — как у обычного заезда.
10. **Симулятор CPS** (WRK-09 п.12, дополнение к DEV-09): мощность и обороты шатуна 1 Гц, сценарии DEV-09 п.3, инъекция часов; доступен в строках разработчика рядом с эмулятором станка (DEV-09 п.6, T-150) — если не укладывается, сообщить менеджеру, вынесем отдельной задачей.

## Критерии приёмки

- REQ-WRK-09 п.1 — `[авто]`: фикстуры «только CPS» → `power_meter`; «FTMS без `0x2AD9`» → `power_meter`; «станок без канала управления» (общее правило, фейк) → `power_meter`; «FTMS с `0x2AD9` и CPS» → `smart`; «только HRS и CSC» и «ничего» → сессии нет; управляемый станок, подключившийся во время `power_meter`, — ни одного `write`. Фикстура «FE-C без FEC3» — в T-167.
- REQ-WRK-09 п.2 (логика исходов, без UI), FRD-01 п.4 — `[авто]`: четыре исхода модели старта для плана и свободной езды, с запомненным станком и без; «подключение» / «переподключение» — неподключённый источник.
- REQ-WRK-09 п.3, WRK-01 п.6 — `[авто]`: тест эквивалентности п.3 (`smart` на `FakeTrainer` и `power_meter` на симуляторе CPS дают одинаковые шаги, цели, события, время завершения; 150 Вт при 110 % → 165 не позже следующего сэмпла).
- REQ-WRK-09 п.4 — `[авто]`: сценарий п.4 целиком — в журнале `StubBleBridge` ни одного `write`; `subscribe` только на характеристики данных; ни одного `subscribe` на `0x2AD9`, `0x2A66`.
- REQ-DEV-10 п.4 — `[авто]`: фикстура FTMS без `0x2AD9` — за подключение нет `subscribe` и `write` на `0x2AD9`, состояние «подключено», телеметрия разбирается; «включить ERG» и смена сопротивления команд не создают.
- REQ-WRK-09 п.6 (а)–(в), DEV-05 п.5, DEV-08 (примечание) — `[авто]`:
  - тест п.6 (а): 250 Вт, 90 об/мин, 140 уд/мин, скорость по модели с уклоном ±0.1 км/ч; с CSC — 85;
  - переподключение п.6 (в): 300 ± 1 сэмплов, «нет данных» в 101…130 с, ни одного `write`.
- REQ-WRK-09 п.6 (б) с У-32 (DEV-05 п.2 (б)–(г) в `power_meter`, D3D-02 п.7) — `[авто]`:
  - CPS и станок без канала управления, CPS обрывается → со следующего сэмпла мощность станка, после возврата CPS — снова CPS;
  - только CPS, CPS обрывается → «нет данных», скорость сцены не позже 30 с равна 0, дистанция не растёт;
  - в обоих случаях шаги сменяются по времени, автопаузы нет.
- REQ-WRK-09 п.7 (модель и журнал) — `[авто]`: тест эквивалентности свободной езды («горы», 600 с, 200 Вт, 75 кг; дистанция, высота, уклон ±0.01; 5 % → 15.2 ± 1.5 км/ч), журнал моста без `write`.
- REQ-WRK-09 п.8, LOC-01 п.1 — `[авто]`: `get_ride` → `trainer_mode = power_meter`; старый заезд без поля → `smart`; FIT — `record` = сэмплы, `power` совпадает, «нет данных» = invalid, `lap` по шагам; при `trainer_source = ble` выгрузка в очереди.
- REQ-WRK-09 п.11 — `[авто]`: в строковых литералах `src/session/`, `src/domain/`, `src/ui/` нет `0x1818`, `2a63`, `2a66`; архитектурные тесты зелёные.
- REQ-WRK-09 п.12 — `[авто]`: симулятор CPS со сценариями DEV-09 п.3 и инъекцией часов; на нём проходят п.1–8.
- Регрессия: WRK-01..08, DEV-02 п.1–5, DEV-05 п.1–3, DEV-08, DEV-09, LOC-01..05, STR-02..05, FRD-04, FRD-07, NFR-06; полный прогон GUT зелёный.
