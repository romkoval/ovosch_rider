## Карточка

> Заголовок карточки до разделения: T-161 — Возможности FTMS-станка от самого станка, а не от констант Neo `[integration]` — `todo` — P1 (MVP, дефект совместимости)

Срез 0.4; код — в паузах 0.3, без железа (на `StubBleBridge` и фикстурах), до T-116b и T-117. Исполнитель — developer. Размер M. Источник — уточнение владельца 2026-10-04 (У-23: целевое устройство — любой FTMS-станок, Tacx Neo — эталон ручной проверки) и REQ-DEV-10 (requirements 53a21f8, bb02a62). Станки без FTMS (Tacx FE-C over BLE, Wahoo legacy, ANT+ FE-C) — после MVP (Н-62), в задачу не входят.
Что сейчас (по коду, для старта). `TrainerDevice.MAX_TARGET_POWER_W` = 2000 (`src/devices/trainer_device.gd:61`) ограничивает цель в `ble_trainer.gd:199` и `fake_trainer.gd:157` — константа подменяет ответ станка (DEV-10 п.7). `0x2AD8` не читается. `0x2ACC` читается, но только ради бита 13 (SIM); бит 3 (Power Target Setting) не учитывается. В `_on_services_discovered` подписка на `0x2AD9` и Request Control идут всегда, без проверки наличия Control Point, а CONNECTED ставится только по успешному ответу Request Control — станок без Control Point навсегда остаётся в CONNECTING. `0x2AD6` и `0x2AD5` уже читаются (В-11, FRD-04 п.3).
Что сделать.
1. Кодек: `decode_supported_power_range` (`0x2AD8`: min, max — sint16 LE, Вт; increment — uint16 LE) и функция ограничения цели: [min; max], округление к ближайшему min + k × increment (DEV-10 п.6). Числа и байты — по п.6, 7 (`05 60 09`, `05 19 00`, `05 82 00`, `05 DC 05`, без `0x2AD8` — `05 D0 07`).
2. `BleTrainer`: читать `0x2AD8`, если характеристика заявлена; диапазон цели — из неё, без неё — запасной 0..2000 Вт, шаг 1 (п.7; число подтверждается в Н-61 (а)). `MAX_TARGET_POWER_W` перестаёт быть пределом для `BleTrainer`: либо переименовать в запасной диапазон, либо убрать из интерфейса (решает developer; `FakeTrainer` получает свой эмулируемый диапазон, по умолчанию — тот же запасной). Первое ограничение за сессию — одна запись в лог, не ошибка пользователю.
3. Бит 3 Target Setting Features = 0 → `0x05` не отправляется ни разу, ERG недоступен. Если `0x2ACC` нет или ответ не пришёл — возможности по наличию `0x2AD9`; ответ `80 05 02` на Set Target Power — ERG недоступен до конца подключения, сообщение пользователю по DEV-02 п.3 (п.5).
4. **Перенесён в T-152 (2026-10-07, У-29; DEV-10 п.4 — по справке requirements «REQ → задачи»). Здесь — только регрессия.** Было: без `0x2AD9`: ни `subscribe`, ни `write` в Control Point (в том числе Request Control); подписка на `0x2AD2` (и `0x2ADA`, если есть); станок переходит в CONNECTED как источник данных; ERG, сопротивление и SIM недоступны: `set_target_power`, `set_resistance_level`, SIM команд не создают (п.4, DEV-02 п.1).
5. Без `0x2AD2` — не CONNECTED, ошибка подключения, нет подписок и записей в `0x2AD9` (п.3; текст причины — как Н-55 / T-154).
6. Возможности станка доступны через интерфейс `TrainerDevice` (например `get_capabilities()`: данные, ERG, сопротивление, SIM, диапазон мощности), чтобы сессия и UI не знали реализацию (DEV-09 п.1, NFR-06 п.3). В этой задаче UI не меняется: переключатель ERG на HUD при недоступном ERG, показ ограниченной цели на HUD (HUD-01), запись цели в сэмпл (WRK-08 п.2) и FIT — T-162 (Н-61 (б) решён владельцем: везде фактически заданное станку значение). T-161 только даёт это значение через интерфейс (п.6 ниже). Поведение сессии по плану и свободной езды со станком без Control Point — REQ-WRK-09 (Н-53, ещё не заведён) и T-152; здесь — только отсутствие команд и разбор данных.
7. П.8: прогнать фикстуры `0x2AD6` 0..20.0, шаг 1.0 (`00 00 C8 00 0A 00`): 50 % → `04 64`, 100 % → `04 C8`; и `0x2AD5` по FRD-04 п.3. Если нынешнее масштабирование (В-11, `FtmsCodec.percent_to_resistance_level`) не учитывает increment или даёт другие байты — исправить; числа Neo (0..100.0) остаются примером фикстуры. Бит 2 «Resistance Target Setting Supported» и поведение при выключении ERG / на шаге FreeRide у станка без сопротивления — по Н-61 (в); до ответа не трогать.
8. Тест по DEV-10 п.2: в строковых литералах `src/devices/` и `src/session/` нет названий моделей и производителей.
Файлы: `src/devices/ble/codecs/ftms_codec.gd`, `src/devices/ble_trainer.gd`, `src/devices/trainer_device.gd` (возможности, запасной диапазон; после T-160), `src/devices/fake_trainer.gd` (свой диапазон; после T-160), `src/devices/ble/ble_uuids.gd` (UUID `0x2AD8`, если его нет), фикстуры станков в `tests/fixtures/` (имя, набор характеристик, байты ответов `read_characteristic`), `tests/unit/devices/`, `tests/integration/`.
Закрывает: REQ-DEV-10 п.3–8 (п.6 — только значение команды; п.7 — запасной диапазон по предложению; п.4 — без поведения сессии по WRK-09), REQ-DEV-02 п.1 (Control Point — только при наличии); регрессия DEV-02 п.2–5, DEV-10 п.1, 2, WRK-02 п.1, WRK-04 п.2, WRK-07 п.2, FRD-04 п.3, 6, NFR-01, NFR-06. П.9 — ручная проверка на эталонном Neo в протоколе T-117.
Критерии авто:
- байты команд п.6, 7 для обоих диапазонов фикстур и без `0x2AD8`; цель 2400 Вт при диапазоне 0..2500 уходит как `05 60 09`;
- бит 3 = 0: план из трёх шагов с целями — в журнале моста нет `0x05`; `80 05 02` — дальше `0x05` не уходит, пользователю — ошибка команды;
- фикстура без `0x2AD9`: за всё подключение нет `subscribe` и `write` на `0x2AD9`, состояние CONNECTED, телеметрия разбирается; «включить ERG» и смена сопротивления команд не создают;
- фикстура без `0x2AD2`: не CONNECTED, ошибка подключения, нет подписок и записей в `0x2AD9`;
- фикстуры `0x2AD6` п.8 — байты `04 64`, `04 C8`;
- одинаковый журнал моста для разных имён и `0x2A29` (DEV-10 п.2); поиск названий моделей пуст;
- приёмки T-016, T-017, T-020, T-024, T-026 и FRD-04 зелёные; тест архитектуры зелёный; полный прогон зелёный.
Ручная — владелец на Neo (T-117, DEV-10 п.9): прочитанные `0x2AD8`, `0x2AD6`, `0x2AD5`, Target Setting Features — в протокол; Neo — в список «Проверено на устройствах».

## Доработка по У-35/У-36 (2026-10-10)

Решения владельца 2026-10-10 (`requirements.md`, журнал «Станок без ERG и цель по станку»): **У-35** — без диапазона мощности (`0x2AD8` нет / нет ответа; у FE-C диапазона нет) запасной 0..2000 Вт, шаг 1 Вт (п.2 выше сделан по предложению — теперь это решение, кода не меняет, только снять пометку «подтвердить» в тестах, если есть); **У-36** — станок с управлением, но без ERG, едет на фиксированном сопротивлении с уровнем пользователя, как при ручном выключении ERG. Порядок: tester принимает T-161 по критериям выше; доработка — следующим коммитом developer поверх, затем повторная приёмка по критериям этого раздела. HUD, сообщение, событие заезда — T-162 (доработка по У-37); флаг ERG сэмпла по факту — T-176.

Что сделать (исполнитель — developer; `[integration]` + сессия):
1. «ERG недоступен» — единый признак возможностей станка в `TrainerDevice` (FTMS: бит 3 `0x2ACC` = 0 или ответ `80 05 02` на `0x05`; FE-C: бит 1 страницы 0x36 = 0 или статус `02` страницы 0x47 на 0x31) и сигнал о его смене посреди подключения. Сессия реализацию не знает (NFR-06 п.3).
2. Переход на сопротивление (DEV-10 п.5 (а), WRK-02 п.7, WRK-04 п.5): Set Target Resistance Level (FTMS `0x04`, FE-C 0x30) с уровнем профиля — не позже 1 с после старта (ERG недоступен с подключения) или после ответа-отказа (посреди заезда); после этого ни одной Set Target Power (`0x05` / 0x31): ни на границах шагов и рампах, ни после FreeRide (`set_erg_enabled(true)` не уходит), ни при множителе WRK-07, ни после паузы (WRK-05 п.3 повторяет уровень). `+`/`−` — сразу по WRK-04 п.2 (п.3 «копить до выключения ERG» не действует), уровень сохраняется в профиле. Таймер, план и запись не прерываются; станок остаётся «подключено» (DEV-07), отдельной ошибки подключения нет.
3. Цель шага для HUD и сэмпла считается как раньше (WRK-02 п.1, 3, 4) — без ограничения DEV-10 п.6 (станку не передаётся).
4. FE-C (DEV-11 п.7 (б), п.8): статус `02` 0x47 → ERG недоступен до конца подключения, 0x30, дальше 0x31 нет (вместо прежней ошибки команды); без бита 1 в 0x36 — ERG недоступен с подключения. Код FE-C — `src/devices/ble/fec_control.gd`, `src/devices/ble/codecs/fec_codec.gd` (владелец кода — T-168, `done`; правка — здесь).
5. Переподключение (DEV-10 п.5 (д), DEV-08): после каждого `connected` возможности определяются заново (чтение `0x2ACC` / запрос 0x36); ERG снова доступен — ERG возвращается по WRK-03 (Set Target Power цели текущего шага по п.6), нет — снова фиксированное сопротивление. Подключение = интервал от `connected` до `disconnected`. Толкование реестра — Н-77 (а); до ответа — так.

Критерии приёмки доработки:
- REQ-DEV-10 п.5 (а), (г) — `[авто]`: FTMS, бит 3 = 0, уровень 50 %, план «60 с 150 Вт, 60 с FreeRide, 60 с 250 Вт» → `04 80` не позже 1 с после старта, ни одного `0x05` за заезд, цели сэмплов 150 / «нет данных» / 250; бит 3 = 1, `05 96 00` принят, `80 05 02` на `05 FA 00` на 61-й секунде → `04 80` не позже 1 с после ответа, дальше `0x05` нет, цель сэмплов с t ≥ 62 — 250. Флаг ERG сэмплов в этих сценариях проверяется в T-176.
- REQ-DEV-11 п.7 (б), п.8 — `[авто]`: тот же сценарий на FE-C — фикстура 0x36 `36 FF FF FF FF 00 00 05` (без бита 1) и фикстура со статусом `02` в 0x47: страница 0x30 вместо `0x04`, ни одной 0x31 после отказа; без 0x36 / без ответа — режимы доступны, отказ ловится по 0x47. П.8 запасной диапазон: 2400 Вт → байты 6–7 0x31 `40 1F`, на HUD и в сэмпле 2000 (в части HUD — T-162).
- REQ-WRK-02 п.7 — `[авто]`: при ERG недоступен п.1–5 WRK-02 команд не создают (рампа, FreeRide → следующий шаг с целью, множитель, пауза/возобновление).
- REQ-WRK-04 п.5 — `[авто]`: уровень профиля 35 %, `0x2AD6` 0..100.0 шаг 0.1, бит 3 = 0 → `04 59` не позже 1 с после старта; `+` → 40 % → `04 66` не позже 1 с, 40 % сохранено в профиле; FE-C без бита 1 — 0x30 байт 7 `46`, затем `50`.
- REQ-DEV-10 п.5 (д) — `[авто]`: подключение с битом 3 = 1, отказ `80 05 02` (сопротивление), обрыв, переподключение с битом 3 = 1 → возможности перечитаны, уходит Set Target Power цели текущего шага не позже 1 с после `connected`; переподключение с битом 3 = 0 → `0x05` нет, `0x04` с уровнем пользователя.
- REQ-DEV-10 п.7, DEV-11 п.8 (У-35) — `[авто]`: регрессия байтов запасного диапазона (`05 D0 07`, `40 1F`).
- Регрессия: критерии T-161 выше, приёмки T-168 (DEV-11 п.6–10), WRK-03 п.2–5, WRK-04 п.1–3, WRK-02 п.1–5 со станком с ERG; тест архитектуры; полный прогон GUT зелёный.

Файлы доработки: `src/devices/trainer_device.gd`, `src/devices/ble_trainer.gd`, `src/devices/fake_trainer.gd` (эмулируемое «ERG недоступен» — для T-162 и снимков), `src/devices/ble/fec_control.gd`, `src/devices/ble/codecs/fec_codec.gd`, `src/session/workout_session.gd` (только команды на станок; HUD-часть — T-162, флаг сэмпла — T-176), фикстуры `tests/fixtures/`, `tests/unit/devices/`, `tests/integration/`.
