## Карточка

> Заголовок карточки до разделения: T-149 — ZWO: `SteadyState` с диапазоном `PowerLow`/`PowerHigh` без `Power` `[integration]` — `review` — P1 (дефект)

Срез 0.3, вне волн, **первая** задача developer из обратной связи. Исполнитель — developer. Размер S. Найдено владельцем на 0.3.0-preview.2.
Сдано: 1a61702, полный прогон 3578/3578. Ждёт приёмки tester по критериям ниже.
Симптом. Экспорт Intervals.icu «Активация: 3x6 мин на гоночной мощности» в `.zwo` не импортируется: 9 ошибок «у элемента SteadyState нет атрибута Power», план не создаётся. Тот же план в `.mrc` импортируется. В файле все шаги вида `<SteadyState Duration=… PowerLow="0.45" PowerHigh="0.6" show_avg="1">` — диапазон без `Power`. Внутри шага — `<textevent message="1/3" duration="10"/>` (без `timeoffset`), в заголовке — `<author>`, `<tags/>`. Причина: `src/integrations/workouts/zwo_parser.gd`, ветка `steadystate` (~стр. 269–277), требует `Power`.
Что сделать.
1. Если у `SteadyState` есть `Power`, правило прежнее: диапазон, если он тоже указан, не учитывается. Если `Power` нет, но есть `PowerLow` и `PowerHigh`, постоянная цель — середина диапазона: (0.45 + 0.60) / 2 → 52.5 %, (0.90 + 0.96) / 2 → 93 %. Так тот же сервис выгружает этот план в `.mrc` (52.5 и 92.9 % — округление сервиса). Если указана только одна граница или ни одной — ошибка IMP-05, текст — «нет атрибута Power (или пары PowerLow/PowerHigh)». Правило подтверждает requirements (Н-51); до ответа делать по предложению.
2. `textevent` внутри такого шага становится подсказкой шага по общему правилу IMP-01 п.4: без `timeoffset` — смещение 0, `duration` не учитывается, как сейчас.
3. `show_avg` не учитывается, без ошибки и предупреждения. `<tags/>` (пустой) не ломает разбор. `<author>` идёт в метаданные (IMP-01 п.5).
4. Фикстуры: пара `.zwo` и `.mrc` одного плана из того же экспорта, без персональных данных (`author` удалить или заменить нейтральным). Файлы владельца в репозитории нет — либо владелец передаёт их в сессию, либо `.zwo` собирается по описанию выше, а `.mrc` — по тем же шагам с округлением сервиса.
Файлы: `src/integrations/workouts/zwo_parser.gd`, `tests/fixtures/workouts/` (новая пара), `tests/unit/integrations/` (или каталог тестов парсеров).
Закрывает: REQ-IMP-01 п.1 (правило диапазона — Н-51), п.4, 5, 6; регрессия IMP-05 п.2, IMP-04 п.6.
Критерии авто: новая `.zwo` импортируется без ошибок. Число шагов и длительности совпадают с `.mrc` того же плана (900, 360, 240, …, 600, 600 с — по файлу), цели — в пределах ±1 % FTP. Подсказки «1/3» и далее привязаны к своим шагам. `SteadyState` с `Power` и диапазоном берёт `Power`. Одна граница без `Power` даёт ошибку IMP-05 с номером строки. Сериализация `to_dict()/from_dict()` новой фикстуры без потерь. Все прежние фикстуры ZWO, а также приёмки T-037 и T-113 — зелёные.
Заметка developer: проверить, нет ли диапазонов в других элементах экспорта Intervals.icu (`IntervalsT` и т. п.). Если есть — сообщить менеджеру, это отдельная задача.
