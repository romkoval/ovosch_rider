## Карточка

> Заголовок карточки до разделения: T-150 — Эмулятор станка в release-сборке через скрытые строки разработчика `[game]` — `review` — P1

Срез 0.3, вне волн, после T-149. Исполнитель — developer. Размер S.
Сдано: 537afe6, полный прогон 3573/3573, вошло в 0.3.0-preview.3. Ждёт приёмки tester по критериям ниже. Заметка developer: заезды на эмуляторе в истории не помечены и при привязанной Strava выгружаются автоматически, как настоящие (п.4 сделан «как есть» — ответа Н-52 нет) → отдельная задача T-160.
Почему. Вопрос владельца на 0.3.0-preview.2: как проверить тренировку без станка? Сейчас в release план без станка не запускается («Станок не подключён. Подключите устройства…»). Эмулятор (`FakeTrainer`) есть только при `dev_tools_enabled` = `is_debug_build()` (`src/app/main.gd`, `src/ui/plan/plan_screen.gd`, `src/ui/home/home.gd`), а CI собирает только release. Владелец не может проверять тренировки и свободную езду на сборке из CI, пока не готова сессия на Neo (0.4). Фича «Тренировка без умного станка» — T-151..T-153; эта задача — только инструмент проверки.
Что сделать.
1. В скрытых строках разработчика «О программе» (открываются 5 нажатиями на «Версию»; там уже «Замер FPS» и «Ограничить FPS до 15» — T-116a) — переключатель «Эмулятор станка» / "Trainer emulator". По умолчанию выключен. Не сохраняется: действует до перезапуска.
2. Включённый переключатель даёт в release то же, что `dev_tools_enabled` даёт в отладочной сборке, но только для эмулятора: «На эмуляторе» и «Эмулятор» в диалоге выбора станка на экране плана, запуск свободной езды с `FakeTrainer` (FRD-01 п.4). Как передать флаг (`AppState` или оболочка `main.gd`) — решает developer, с соблюдением DEV-09 п.1: выбор реализации станка — только в `src/devices/`. Прочие инструменты «Режима разработки» главного экрана в release не открываются.
3. Пока эмулятор включён, на экране плана и на HUD видна пометка «Эмулятор» — чтобы фиктивный заезд не приняли за настоящий. Где и как — по `ui.md`; если макета нет, нейтральная метка режима, как у T-103.
4. Заезд на эмуляторе сохраняется и выгружается так же, как в отладочной сборке сейчас. Правило автовыгрузки в Strava — по ответу Н-52; если ответа нет к сдаче, оставить как есть. (Сдано «как есть»; метка и правило выгрузки — T-160.)
5. Переводы ru/en.
Файлы: `src/ui/settings/{about_diagnostics,settings_screen}.gd` (строка), `src/app/main.gd` (флаг), `src/ui/plan/plan_screen.gd`, `src/ui/home/home.gd` (только чтение флага, если нужно для свободной езды), `assets/i18n/strings_menu.csv`, тесты.
Закрывает: REQ-DEV-09 п.6 и REQ-FRD-01 п.4 — расширение на release-сборку по Н-52 (формулировку подтверждает requirements, работу не держит); регрессия UIX-05, NFR-08, тест архитектуры (NFR-06).
Критерии авто (сборка не отладочная, `dev_tools_enabled` = false):
- По умолчанию кнопок эмулятора нет, текст диалога — release.
- После включения переключателя «На эмуляторе» видна, тренировка стартует с `FakeTrainer` и идёт до конца (как WRK-01 п.5); свободная езда стартует с `FakeTrainer`.
- Новый экземпляр оболочки (перезапуск) — переключатель выключен.
- Строки разработчика без 5 нажатий не видны (регрессия T-116a).
- В профиль и в настройки ничего не пишется.
Проверка экспорта: локальный экспорт Linux release (как в T-147) запускается, переключатель работает. После T-148 — тем же дымовым прогоном.
Ручная проверка — владелец на сборке из CI: включить эмулятор, проиграть план и свободную езду, сохранить, экспортировать FIT.
