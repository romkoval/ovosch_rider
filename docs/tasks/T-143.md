Волна 4 (TA-2, после T-106a1; параллельно с T-106a2 — файлы не пересекаются). Исполнитель — technical-artist. Размер M. Зависит **строго** от T-106a1: эталоны конвейера — `rider_rig_reference.glb` (25 костей rest), `bike_reference.glb` (седло и ручки для шага 5), `rider_atlas_id.png` и таблица регионов (шаг 8). T-106a2 **не нужен**: синтетический вход строится в `bpy` по эталону скелета, а не из манекена (манекен — жёсткие части, а не слитый скан). T-106a4 нужен только для сквозной проверки в Godot (импорт + Т8 + `[авто]` п.1–5): если к сдаче T-143 он не готов — сквозная проверка переносится первым шагом T-106b′, T-143 этим не блокируется.
Почему. Вариант Г: модель доводит TA скриптами, повторяемо (сырой файл можно заменить и прогнать заново); сырьё владельца придёт позже — конвейер должен быть готов и проверен до него, чтобы T-106b′ была прогоном и правками, а не разработкой.
Что сделать.
1. Скрипты `bpy`, headless: `/opt/bpy/bin/python` (облако, `scripts/cloud/setup.sh`) или `blender -b --python` (Mac владельца) — поиск интерпретатора в одном месте, переменная `BLENDER_PY` переопределяет. Шаги конвейера «Вариант Г» спеки как отдельные инструменты с общим отчётом: **1** проверка сырья (метрики по чек-листу `rider-photo-guide.md` раздел 6 п.5: высота, число оболочек, дыры, несвязные куски, слипшиеся руки/ноги по сечениям, текстура, поза; сравнение 2–3 вариантов); **2** очистка и нормализация (метры, оси брифа §4, срез плиты пола и внутренних оболочек, закрытие дыр, разделение тело / волосы / туфли с крышкой стопы); **3** пропорции (временная арматура по ориентирам суставов — файл ориентиров `landmarks.json` рядом с сырым файлом: генерирует синтетика или правит TA; длины звеньев и обхваты — к таблицам спеки, рост контракта 1.78 м); **4** ретопология проекцией (наша базовая low-poly сетка человека с кольцами сгиба и рёбрами по границам регионов, генерируется скриптом; shrinkwrap + сглаживание; запасной режим — децимация); **5** посадка в rest (A-поза → поза контракта по `rider_rig_reference.glb`, применение как rest; таз и шорты не проходят сквозь седло `bike_reference.glb`); **7** веса (автоматические + ограничение ≤ 4 влияний, нормализация, отчёт по контрольным позам спеки); **8** регионы (границы по размерам спеки, цвет текстуры — подсказка для кожи, перчаток, волос; UV0 по атласу: U — колонка, V — тон; текстура и исходная UV удаляются; один материал `M_rider`); **11** сборка и экспорт `rider.glb` по брифу §12 и `.blend`, затем проверки Т1–Т7 на стороне Blender (имена и родители костей, rest ±1 мм от эталона, бюджеты по сеткам, один материал, нет `COLOR_0` и текстур, грань внутри колонки с отступом 10 %, нет весов на сокетах, масштаб 1) и, если есть, `scripts/rider_check.sh` T-106a4. Шаги 6, 9, 10 (кисти, экипировка, `body_f`) — не здесь: это T-106c′.
2. Запуск одной командой: `scripts/rider_refine.sh <сырой.glb> [--landmarks <json>] [--from N] [--to M] [--work <каталог>]` — все шаги по порядку или диапазон; на каждом шаге — промежуточный `.blend` и строка отчёта (что сделано, метрики, предупреждения); ошибка — номер шага, объект, что не так.
3. Синтетический «сырой» вход (без файлов владельца): генератор `bpy` строит фигуру по эталону скелета с намеренно «чужими» пропорциями (рост ≠ 1.78), A-поза, всё слито в одну треугольную сетку (remesh), с плитой пола, внутренней оболочкой, дырой, «варежками» кистей, запечённой светотенью в текстуре, ориентирами `landmarks.json`; экспорт в GLB как у сервисов (+Y вверх, сантиметры — отдельным вариантом). Плюс испорченные копии для шага 1 (нет текстуры, слипшиеся ноги, две несвязные фигуры).
4. Хранение: промежуточные `.blend` и отчёты — **вне репозитория**, по умолчанию `reference/ai/work/<имя сырого>/NN_<шаг>.blend` (каталог `reference/` в `.gitignore`); в репозиторий — только скрипты, базовая сетка шага 4 (если сгенерирована кодом — не хранится) и синтетика (генерируется, не хранится). Итоговый `rider.glb` / `.blend` в `assets/rider/` T-143 не кладёт: это T-106c′ после записи п.9 (а) и ответа Н-45.
5. Числа спеки, которых нет в пакете T-106a1 (границы регионов по высоте, бюджеты сеток, обхваты), — в одном файле данных конвейера со ссылкой на подраздел спеки у каждого числа; тест сверки с тем, что уже есть в коде (`rider_rig_contract.gd`, таблица регионов) — расхождение = падение.
6. Краткая инструкция TA в `scripts/blender/README.md` (запуск, ориентиры, где лежат промежуточные файлы, как продолжить с шага N).
Файлы: `scripts/blender/**` (новый: пакет шагов, генератор синтетики, данные конвейера, `README.md`), `scripts/rider_refine.sh` (новый), `scripts/blender/tests/**` (unittest под `bpy`, запуск `scripts/blender/test.sh`); `scripts/cloud/setup.sh` — только если нужен поиск интерпретатора. Закрывает: механизм REQ-D3D-09 п.7 (бюджеты, кости, материал при сборке) и п.9 (сырьё и промежуточные файлы вне репозитория; основание прав не подменяется — записи в T-106c′); проверка п.1–5 — на синтетическом выходе (rest ±1 мм от эталона скелета в Blender; сквозная в Godot — при готовом T-106a4).
