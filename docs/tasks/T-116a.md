## Карточка

> Заголовок карточки до разделения: T-116a — Ядро диагностического журнала и журнал кадров `[game]` — `review` — P0

Срез 0.3 (технический хвост), волна 2. Исполнитель — developer. Размер S–M. Сдано: dc8c68c (журнал кадров, «Замер FPS»; ветка `wip/t-116a-t-108`, полный прогон 3418/3418, перенесено в рабочую ветку 2026-10-04); ждёт приёмки tester.
Почему. Критерий выхода 0.3 — 60 FPS на эталонном Mac после нового гонщика и леса (D3D-05 п.1, D3D-07 п.7, D3D-08 п.9), а инструмента замера на машине владельца нет; бюджет спек T-104/T-105 без базового замера — догадка. Способа принудительно снизить FPS (NFR-02 п.3) тоже нет. Ядро журнала (файл, ротация, фильтр секретов, экспорт) нужно и BLE-части T-116b.
Что сделать.
1. Модуль журнала: файл на запуск в `user://logs/`, ротация, предел объёма; API записи событий с меткой времени и категорией (категории BLE добавит T-116b); слой — по правилам NFR-06 п.3 (на выбор developer, обоснование в отчёте).
2. Без секретов: значения из `SecureStore`, заголовки `Authorization`, коды OAuth в журнал не пишутся (фильтр + тест).
3. Статистика кадров за заезд (тренировка и свободная езда): средний FPS, 1 % худших кадров, доля кадров > 16.7 мс и > 33 мс, рендерер, разрешение окна и 3D, трасса — в журнал при завершении заезда (методика `docs/perf_budget.md`).
4. «Замер FPS» без станка: скрытый пункт (в «О программе» или разделе разработчика по `ui.md`; доступен и в release-сборке): сцена заезда на выбранной трассе (по умолчанию «Перевал») с постоянной скоростью заданное время (по умолчанию 3 мин), затем статистика п.3 в журнал и на экран.
5. Отладочная настройка «ограничить FPS до 15» (для NFR-02 п.3) — не видна в обычном меню.
6. Экспорт: «Сохранить журнал» в «О программе» через системный диалог; переводы ru/en.
Файлы: модуль журнала (слой по NFR-06 п.3), `src/ui/settings/**` (кнопки «О программе»), `src/ui/{workout,free_ride}/*_screen.gd` (только вызов статистики кадров), `assets/i18n/strings_menu.csv`, тесты. `src/devices/ble/` не трогает (T-116b).
Закрывает: инструмент для ручных критериев D3D-05 п.1, 3, D3D-07 п.7, D3D-08 п.9, NFR-02 п.3; регрессия NFR-05 п.1, NFR-06 п.3. REQ на журнал — вопрос Н-27.
Критерии авто: заезд на синтетических кадрах даёт в журнале запись статистики с полями п.3 (значения сходятся с поданной серией длительностей кадров); «Замер FPS» headless на короткой длительности завершается и пишет статистику; поиск значений тестовых секретов в журнале пуст; ограничение FPS 15 — поток 1 Гц без пропусков (как NFR-02 п.1, 2); ротация не превышает предел; экспорт копирует журнал в выбранный путь; тест архитектуры зелёный. Ручные: замер владельцем на эталонном Mac — MacBook на базовом M1 — база, после T-106a3 и T-107 (условие выпуска 0.3) и после T-106c′ (итоговая модель; 0.3 или 0.3.1 — Н-33).
